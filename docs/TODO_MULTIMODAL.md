# 短期开发计划：多对话 + 多模态

> 更新日期：2026-04-24

## 背景

当前系统已完成基础的飞书消息接收和意图识别。下一步需要实现：
1. **多对话管理** - 支持历史查询、新建对话等
2. **多模态输入** - 支持语音和图片输入

---

## 一、多对话功能

### 1.1 需求分析

用户场景：
- 用户可以在飞书中发起多个独立会话（类似微信对话）
- 每个会话有独立的历史记录
- 支持会话置顶、删除、重命名
- 会话列表按更新时间排序

### 1.2 技术方案

**数据库表（已有）:**
- `sessions` 表已存在，包含 `id`, `user_id`, `title`, `is_pinned`, `last_intent`, `created_at`, `updated_at`
- `tasks` 表存储会话内的任务/消息历史

**需要实现的 API：**

| 路由 | 方法 | 说明 |
|------|------|------|
| `GET /api/v1/sessions` | GET | 获取会话列表（分页） |
| `POST /api/v1/sessions` | POST | 创建新会话 |
| `PATCH /api/v1/sessions/{id}` | PATCH | 更新会话（标题、置顶） |
| `DELETE /api/v1/sessions/{id}` | DELETE | 删除会话 |
| `GET /api/v1/sessions/{id}/messages` | GET | 获取会话历史消息 |

**飞书集成：**
- 机器人收到消息时，根据 `session_id` 或创建时间关联到对应会话
- 会话 ID 可以通过飞书消息的 `chat_id` 或自定义会话标识映射

### 1.3 实现步骤

- [ ] **Step 1**: 完善 `sessions.py` CRUD 接口实现
- [ ] **Step 2**: 实现会话-飞书 chat_id 映射逻辑
- [ ] **Step 3**: 修改 `feishu_ws.py` 支持多会话上下文
- [ ] **Step 4**: 会话历史消息存储与查询
- [ ] **Step 5**: 前端对接（如果需要）

## 二、多模态输入

### 2.1 需求分析

用户场景：
- 用户发送语音消息，AI 自动识别内容并回复
- 用户发送图片，AI 能看懂图片内容并回答
- 语音和图片需要转写/识别后交由 LLM 处理

### 2.2 技术方案

**语音识别：**
- 飞书消息支持语音类型 (`audio`)
- 需要调用飞书音频转文字 API 或使用其他 ASR 服务
- 火山引擎也有语音识别能力

**图片理解：**
- 图片消息类型为 `image`
- 需要先下载图片，然后作为 base64 或 URL 传给多模态 LLM
- 火山引擎 `ep-20260423222610-xbx2l` 是否支持多模态需要确认

**处理流程：**
```
用户发送语音/图片
    ↓
飞书推送消息事件 (message_type: audio/image)
    ↓
下载媒体文件
    ↓
调用 ASR/OCR 服务转文本
    ↓
将文本 + 图片信息输入 LLM
    ↓
生成回复
```

### 2.3 实现步骤

- [ ] **Step 1**: 飞书消息类型扩展支持（audio/image）
- [ ] **Step 2**: 媒体文件下载服务
- [ ] **Step 3**: 语音转文字（ASR）集成
- [ ] **Step 4**: 图片理解集成
- [ ] **Step 5**: 修改意图识别支持多模态意图
- [ ] **Step 6**: 修改 `feishu_ws.py` 处理流程

## 四、注意事项

1. **飞书权限**：需要申请 `im:message` 媒体读取权限
2. **Token 管理**：媒体下载需要 fresh access_token
3. **文件存储**：大文件可能需要临时存储方案
4. **火山引擎模型**：确认是否支持 `ep-20260423222610-xbx2l` 的多模态能力
