# 产品方案讨论记录：NovaMind Workspace 团队知识助手

时间：2026-05-04 14:00 - 14:35
参与人：Lina（PM）、Bo（工程）、Iris（设计）、Ken（销售）

## 聊天记录

Lina：这周想把团队知识助手的方案收一下，目标是先服务 20 到 50 人的小团队。

Ken：销售侧最常被问的是“能不能把公司文档传进去直接问”，所以 RAG 一定要放在第一优先级。

Bo：可以先做文档上传、切块、检索和会话页，权限先简单一点，按团队隔离。

Iris：如果 first run 太复杂，用户第一次进来会懵。我建议首页只有两个主动作：上传资料、开始提问。

Lina：同意。团队管理可以先放到二级入口，不要一开始就让用户填很多信息。

Ken：还有一个点，客户会默认拿它跟大模型官网聊天页比较，所以回答速度不能太慢。

Bo：那就别在 v1 上太多链路。先不要上复杂 agent，先把“问得准”和“传得上去”做好。

Iris：从交互上看，如果上传完没有明显反馈，用户会以为失败。需要一个很清楚的处理状态。

Lina：这里我记一下，上传完成后给三个状态：处理中、可提问、失败。

Ken：PoC 客户还会问团队能不能共享同一批资料。

Bo：可以，一个 team 下面挂一个共享知识库就够了，先不做细粒度文件权限。

Lina：那这版范围基本清楚了：团队级知识库、会话页、上传状态、基础团队管理。

Iris：视觉上我希望不要太像普通聊天框，左侧可以放知识库和历史会话，让它更像工作台。

Bo：技术上没问题，但请控制在现有前端结构里，先别重做太多页面骨架。

Ken：最后提醒一下，报价时最好把“共享知识库”和“团队空间”作为企业版卖点。

Lina：好，我来整理方案。结论是 v1 先做一个轻量但完整的团队知识助手闭环。

## 会议结论

- v1 优先做团队级 RAG 问答
- 首页聚焦“上传资料”和“开始提问”
- 暂不引入复杂 agent 流程
- 会话与知识库采用团队隔离
- 上传状态必须可感知
